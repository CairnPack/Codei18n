# 规范增量：语言 adapter

## 新增需求

### 需求：目标语言支持

系统应支持 Kotlin（.kt .kts）、Java、TypeScript（.ts .tsx .mts .cts）、JavaScript（.js .jsx .mjs .cjs）、Dart、C# 的注释提取，并识别各自的文档注释。

#### 场景：C# XML 文档注释
- **当** 源码中有连续三行 `///`
- **那么** 提取为一条 type=doc、parts=3 的记录

#### 场景：字符串中的伪注释
- **当** 字符串字面量（含原始字符串、多行字符串）中出现 `//` 或 `/* */`
- **那么** 不被提取

### 需求：统一的连续行注释合并

所有语言的连续行注释按 docs/index-format.md §6.1 合并，行尾注释不合并。

#### 场景：行尾注释
- **当** `x = 1 // a` 的下一行是 `// b`
- **那么** 二者各为一条记录

### 需求：符号稳定

移动代码行不应改变注释的符号与 ID。

#### 场景：在上方插入空行
- **当** 在注释上方插入若干行
- **那么** 注释 ID 不变

### 需求：规则调整后保留已有译文

合并规则或符号规则调整导致 ID 变化时，map update 应从旧 ID 继承已有译文。

#### 场景：旧版本逐行翻译过的注释
- **当** 旧版本已为两行 `//` 分别生成译文，升级后再次 map update
- **那么** 合并后的条目直接获得按行连接的译文，不产生新的翻译任务
