# 规范增量：性能

## 新增需求

### 需求：并行与增量扫描

扫描必须并行解析文件，并复用未变化文件的上次解析结果。

#### 场景：首次全量扫描
- **当** 在 8 核机器上扫描约 2000 个文件的样例项目
- **那么** 耗时不超过重构前顺序扫描的 1/3

#### 场景：无改动重扫
- **当** 源码未改动时再次扫描
- **那么** 耗时不超过全量扫描的 10%，且不重写 mappings.json 与 index.json

### 需求：翻译去重与保存节流

归一化后相同的待翻译原文只请求一次；翻译过程中按批次数或时间节流保存，结束时必定保存。

#### 场景：同文注释
- **当** 10 条注释原文归一化后相同
- **那么** 只向翻译后端请求 1 次，10 条都写入译文

### 需求：孤儿清理

`map update --prune` 删除源码中已不存在的条目；默认只报告数量。

#### 场景：默认不删除
- **当** 不带 --prune 运行 map update 且存在孤儿条目
- **那么** 条目保留，输出可清理的数量
